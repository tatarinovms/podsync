# Персональные ленты

В **LIBRARY → Персональные ленты** можно создавать независимые RSS-подкасты и вручную добавлять отдельные видео YouTube, VK Video, Rutube, прямые HTTP(S) URL медиафайлов и локальные файлы. Количество лент не ограничено бизнес-логикой.

При первой инициализации хранилища создаётся `personal` — **Моя лента**, формат Audio, RSS `/personal.xml`. Флаг `initialized` и первая лента записываются одной транзакцией BadgerDB. Удаление первой ленты не сбрасывает флаг: после перезапуска она не появится снова. При обновлении старой установки с обычной лентой `personal` запуск сообщает о конфликте; существующая лента не перезаписывается.

Дополнительные ленты получают случайные идентификаторы `personal-<32 hex symbols>`. ID и RSS URL не меняются при переименовании. Для новых обычных лент зарезервированы `personal`, префикс `personal-` и каталог `_personal`.

## Создание и настройки

Нажмите **Создать ленту**, задайте название и Audio/Video. Можно указать описание, загрузить обложку или задать её URL, выбрать порядок эпизодов. Настройки применяются к RSS сразу. Формат определяет обработку новых эпизодов; уже добавленные файлы не перекодируются при смене настройки.

URL добавляется в постоянную очередь Podsync. Используются общие настройки yt-dlp (cookies, proxy, timeout), ffmpeg и настроенное файловое хранилище. Ошибку можно повторить кнопкой **Повторить**. Локальная загрузка принимает один файл в поле `file`, до 4 ГиБ вместе с multipart-запросом. Поддерживаются MP3, M4A/M4B, MP4/M4V, MOV, WebM, MKV, WAV, Ogg, Opus, FLAC и AAC. Audio преобразуется в MP3; Video — в MP4. Для Video нужен видеопоток.

## Копирование, перемещение и удаление

- **Переместить** переносит принадлежность эпизода другой ленте и сохраняет его GUID.
- **Копировать** создаёт отдельное включение с новым стабильным GUID, которое ссылается на тот же медиаобъект.
- Между Audio и Video лентами копируется исходный файл. В RSS сохраняется фактический MIME-тип эпизода.
- Удаление ленты или эпизода требует подтверждения. Если флажок удаления файлов выключен, файлы остаются в хранилище. Если включён, удаляются только файлы без оставшихся ссылок из других лент.
- RSS удалённой ленты удаляется в обоих режимах. Автоматическая очистка `keep_last` к персональным лентам не применяется.

## REST API

Все маршруты используют существующую аутентификацию администратора.

| Метод | Маршрут | Тело / результат |
|---|---|---|
| GET | `/api/v1/personal-feeds` | Массив лент |
| POST | `/api/v1/personal-feeds` | `title`, `format` обязательны; `description`, `cover_art`, `playlist_sort`, `private_feed` необязательны; 201 |
| GET | `/api/v1/personal-feeds/{id}` | `{feed, episodes}` |
| PATCH | `/api/v1/personal-feeds/{id}` | Только изменяемые поля; пропущенные поля сохраняются; ID менять нельзя |
| DELETE | `/api/v1/personal-feeds/{id}?confirm=true&delete_files=true` | 204; `delete_files` по умолчанию false |
| GET | `/api/v1/personal-feeds/{id}/episodes` | Массив эпизодов |
| POST | `/api/v1/personal-feeds/{id}/episodes` | `{ "url": "https://…", "title": "Необязательно" }`; 202 |
| POST | `/api/v1/personal-feeds/{id}/upload` | Multipart, поле `file`; 202 |
| DELETE | `/api/v1/personal-feeds/{id}/episodes/{episode_id}?confirm=true&delete_files=true` | 204 |
| POST | `/api/v1/personal-feeds/{id}/episodes/{episode_id}/copy` | `{ "target_feed_id": "personal-…" }` |
| POST | `/api/v1/personal-feeds/{id}/episodes/{episode_id}/move` | `{ "target_feed_id": "personal-…" }` |
| POST | `/api/v1/personal-feeds/{id}/episodes/{episode_id}/retry` | 202 |

`format`: `audio` или `video`. `playlist_sort`: `desc` (сначала новые, по умолчанию) или `asc`. При создании или переименовании пустое название отклоняется. `cover_art` — HTTP(S) URL; файл обложки можно предварительно загрузить через `/api/v1/covers/upload`.

## Хранение и восстановление

Персональные ленты хранятся в BadgerDB в отдельном пространстве `podsync/personal/v1/`, а обычные подписки по-прежнему настраиваются в `[feeds]` файла TOML. Для резервной копии персональных лент нужны база и файловое хранилище.

- `feed/{id}` — настройки и число включений.
- `episode/{feed_id}/{episode_id}` — GUID, ссылка на медиаобъект, дата добавления.
- `media/{media_id}` — источник, формат, метаданные, состояние загрузки и число ссылок.
- `initialized` — постоянный признак первоначальной инициализации.
- `deleted/{feed_id}` и `delete_pending` — незавершённая очистка, повторяемая после перезапуска.

Файлы находятся в `_personal/{media_id}/`. Пользовательское имя файла не используется как путь. Копирование, перемещение и изменение числа ссылок выполняются атомарно. Сетевая загрузка идёт вне блокировки управления лентами; завершение загрузки не восстанавливает удалённую ленту. Незавершённые задачи восстанавливает существующая очередь Podsync. RSS пересобирается при запуске и после изменений.

Новые MCP-инструменты не добавляются; для персональных лент предназначены отдельный раздел интерфейса и перечисленные REST-маршруты.
