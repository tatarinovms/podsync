# Персональные ленты

[English](../personal-feeds.md) | **Русский**

В Podsync встроен движок **Персональных лент**, позволяющий создавать собственные универсальные подкаст-ленты и вручную собирать в них отдельные эпизоды из видеохостингов, прямых ссылок на аудио/видеофайлы, файлов на сервере и локальных загрузок.

---

## 1. Обзор и возможности

- **Универсальные ленты (Audio + Video)**: Персональные ленты не разделяются жестко на аудио или видео. В одной и той же ленте могут одновременно находиться как аудиозаписи (MP3, OGG, OPUS, WAV, FLAC, AAC), так и видеоролики (MP4, MKV, WebM, MOV). В RSS XML-фиде для каждого эпизода формируется соответствующий MIME-тип тега `<enclosure>` (`audio/mpeg`, `video/mp4` и др.).
- **Интеграция в общую библиотеку**:
  - Отдельная вкладка **Personal feeds** в боковом меню.
  - Персональные ленты отображаются на общей вкладке **Podcasts** с бейджем провайдера **Personal** и отдельной опцией `Personal` в фильтре типов.
- **Способы добавления материалов**:
  1. **Видео и аудио платформы**: Добавление отдельных роликов по ссылке (YouTube, VK Video, Rutube, Vimeo, SoundCloud).
  2. **Прямые ссылки на медиафайлы**: Скачивание файлов по HTTP/HTTPS (MP3, OGG, OPUS, WAV, FLAC, MP4, WebM и др.).
  3. **Локальные файлы на сервере (`file_path`)**: Импорт файлов напрямую из файловой системы сервера через API или MCP.
  4. **Загрузка файлов с компьютера**: Загрузка аудио/видео файлов размером до 4 ГиБ через веб-интерфейс или REST API.
- **Автоматическая конвертация**:
  - Аудиофайлы автоматически приводятся к совместимому MP3 с извлечением длительности и тегов через `ffmpeg`.
  - Видеофайлы упаковываются в MP4 (H.264 / AAC) с созданием превью.
- **Экономия места и совместное использование файлов**:
  - Эпизоды можно **копировать** между лентами без дублирования файлов на диске. Копия получает свой уникальный GUID, ссылаясь на общий медиаобъект.
  - Эпизоды можно **перемещать** в другую ленту с сохранением исходного GUID и даты публикации.
  - Медиафайл удаляется с диска только тогда, когда счетчик ссылок на него становится равным нулю и подтверждено удаление файлов.
- **Инициализация**:
  - Первая лента создается с идентификатором `personal` (**My Feed**) и адресом `/personal.xml`.
  - Все последующие ленты получают неизменяемые случайные идентификаторы `personal-<32 hex-символа>`.
  - Удаление первой ленты сохраняет флаг инициализации, предотвращая повторное создание при перезапуске.

## 2. Управление персональными лентами в веб-интерфейсе

### Создание ленты
1. Перейдите в **LIBRARY → Personal feeds** (или нажмите **Add podcast**).
2. Нажмите **Create feed**.
3. Укажите название, описание, ссылку на обложку (или загрузите файл изображения) и порядок сортировки серий (`Newest first` или `Oldest first`).
4. Нажмите **Create feed**. RSS-лента генерируется немедленно.

### Добавление серий
В детальном просмотре любой персональной ленты доступны:
1. **По ссылке или пути**: Вставьте URL ролика (YouTube, VK, Rutube, прямая ссылка на MP3/MP4) или путь к файлу на сервере, задайте заголовок и формат (опционально) и нажмите **Add episode**.
2. **Загрузка файла с компьютера**: Выберите файл (до 4 ГиБ), укажите заголовок и нажмите **Upload & add**. Прогресс отображается в реальном времени.

### Действия с эпизодами
В карточке каждого эпизода доступны:
- **Аудио / Видео плеер**: Встроенный HTML5-плеер для воспроизведения прямо в браузере.
- **Move**: Переносит эпизод в другую персональную ленту с сохранением GUID.
- **Copy**: Клонирует эпизод в другую ленту с новым GUID без дублирования файла.
- **Retry**: Перезапускает неудачную загрузку или обработку.
- **Delete**: Удаляет эпизод из ленты с опциональным удалением файлов с диска.

### Подписка на персональные ленты
Кнопка **Subscribe** открывает единое фирменное окно подписки:
- Прямой RSS-адрес с кнопкой **Copy**.
- Экранный **QR-код** для быстрого сканирования камерой смартфона.
- Ссылки в один клик для **Apple Podcasts**, **Pocket Casts** и **Overcast**.

## 3. Справочник REST API (`/api/v1/personal-feeds`)

Все маршруты требуют авторизации администратора (Basic Auth или сессионная cookie).

| Метод | Маршрут | Тело / Параметры | Описание |
|---|---|---|---|
| `GET` | `/api/v1/personal-feeds` | Нет | Список всех персональных лент. |
| `POST` | `/api/v1/personal-feeds` | `{"title": "...", "description": "...", "cover_art": "...", "playlist_sort": "desc", "private_feed": false}` | Создает новую ленту (201 Created). |
| `GET` | `/api/v1/personal-feeds/{id}` | Нет | Метаданные ленты и список эпизодов. |
| `PATCH` | `/api/v1/personal-feeds/{id}` | `{"title": "...", "description": "...", "cover_art": "...", "playlist_sort": "asc", "private_feed": true}` | Частичное обновление настроек. |
| `DELETE` | `/api/v1/personal-feeds/{id}?confirm=true&delete_files=true` | Query-параметры | Удаление ленты и RSS. |
| `GET` | `/api/v1/personal-feeds/{id}/episodes` | Нет | Список эпизодов ленты. |
| `POST` | `/api/v1/personal-feeds/{id}/episodes` | `{"url": "...", "file_path": "...", "title": "...", "format": "audio"}` | Добавление эпизода по ссылке или пути к файлу. |
| `POST` | `/api/v1/personal-feeds/{id}/upload` | Multipart form (`file`, `title`, `format`) | Загрузка медиафайла (до 4 ГиБ). |
| `POST` | `/api/v1/personal-feeds/{id}/episodes/{ep_id}/copy` | `{"target_feed_id": "personal-..."}` | Копирование эпизода в другую ленту. |
| `POST` | `/api/v1/personal-feeds/{id}/episodes/{ep_id}/move` | `{"target_feed_id": "personal-..."}` | Перемещение эпизода в другую ленту. |
| `POST` | `/api/v1/personal-feeds/{id}/episodes/{ep_id}/retry` | Нет | Повтор неудачной загрузки серии. |
| `DELETE` | `/api/v1/personal-feeds/{id}/episodes/{ep_id}?confirm=true&delete_files=true` | Query-параметры | Удаление серии из ленты. |

## 4. Инструменты MCP (Model Context Protocol)

ИИ-ассистенты (**Claude Desktop**, **OpenCode**, **Cursor**, **Cline**, **Antigravity**) могут управлять персональными лентами через инструменты:

| Имя инструмента | Аргументы | Описание |
|---|---|---|
| **`list_personal_feeds`** | `{}` | Список всех персональных лент, количество эпизодов, общий вес и RSS URL. |
| **`get_personal_feed`** | `feed_id` *(обяз)* | Метаданные ленты и список всех эпизодов (со статусом, источником и ссылкой). |
| **`create_personal_feed`** | `title` *(обяз)*, `description`, `cover_art`, `playlist_sort`, `private_feed` | Создать новую персональную ленту. |
| **`add_personal_episode`** | `feed_id` *(обяз)*, `url` *(опц)*, `file_path` *(опц)*, `title` *(опц)*, `format` *(опц)* | Добавить эпизод по ссылке или локальному пути к файлу. |
| **`delete_personal_episode`** | `feed_id` *(обяз)*, `episode_id` *(обяз)* | Удалить эпизод из ленты и очистить занятое дисковое пространство. |
| **`rename_personal_episode`** | `feed_id` *(обяз)*, `episode_id` *(обяз)*, `title` *(обяз)* | Переименовать эпизод в персональной ленте. |

## 5. Архитектура хранения

- **Пространство ключей BadgerDB**: `podsync/personal/v1/`
  - `feed/{id}`: Метаданные ленты и число эпизодов.
  - `episode/{feed_id}/{episode_id}`: Запись членства эпизода со ссылкой на медиаобъект.
  - `media/{media_id}`: Источник, статус конвертации, путь к файлу и счетчик ссылок.
  - `initialized`: Постоянный маркер первичной инициализации.
- **Хранилище файлов**:
  - Файлы медиа: `<data_dir>/_personal/{media_id}/file.<ext>`
  - XML-фиды: `<data_dir>/{feed_id}.xml`
